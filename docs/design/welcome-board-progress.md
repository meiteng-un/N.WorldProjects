# WelcomeBoard / 個室カードと復帰先

更新: 2026-10-18。実装済みと構想を分けて記録。

## 確定仕様
- 近付いた本人を自動認証し、カードキーの受取・返却を担当する。
- 個室の指定スタンドに本人のカードを収納している間、個室入口または室内の最後の安全な位置を復帰先にする。
- 死亡時も個室復帰の対象（ユーザー確認済み）。以前の死亡時次元ゲート案を更新。
- カード取外し、権限失効、他人のカードでは個室復帰権を与えない。

## 現状確認
- 701/702のボードは権限Manager・各室グループ・Player ObjectのAuthorityKey・収納Anchorを参照済み。Pool用は別設定。
- 701のAuthorityKey_RoomStandsにNDynamicObjectSnapPointが2件ある。702の旧Cardkey_Receiverと同一機能とは扱わない。
- ボードには保持中/収納済みの再処理防止がある。enableRespawn/RespawnRoomKeyはカード再発行であり、プレイヤー復帰位置ではない。
- SnapPointには占有状態通知・保存復元がある。occupiedLastToucherはカード所有者とは限らないため、認証の代用にしない。
- N.StatusSystem内にはHP0からプレイヤーを復帰させる処理はまだない。

## 今回のソース改善
- OnIdentityCardReadyの外部呼出しでも、既存ManagerのIsUserInGroupによる認証を実行する。
- 共有カード方式では他人の所有者名を上書きして渡さない。
- エディタのLocal Player認証例外はUNITY_EDITOR内のみとし、player compileでは除外する。
- 既存の保持/収納ガードとPlayer Object方式は維持する。
- 最終変更のplayer compile要求後、1,378スクリプトのU#コンパイル完了を確認（56.210秒）。Scene配置は変更していない。実機・再入室・複数人での検証は未実施。

## 残作業
- 本人カードと権限を検証する復帰先コーディネーター、カード取外し時の解除。
- 入口Transformと室内判定範囲、安全な前回位置の保存。推測座標へ転移する設定は作らない。
- 再入室時の個人データとカード収納復元の順序待ち。
- 死亡復帰時のHP回復、空腹/渇きの保持、30分の飢餓/脱水ダメージ免除との連携。
- 実機確認は後でまとめる。今回、個室への復帰機能を実装・適用したわけではない。
