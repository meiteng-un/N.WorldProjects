# Naturlin Unity Skill の運用整理

- 最初に対象プロジェクトと未完了項目を特定する。コンパイル、接続、Scene保存、実機動作は別々に検証する。
- 小さな修正は主担当で続ける。複数人で独立して進められる大きな作業だけ分担する。
- Unityが再読み込み中の場合は、Program Asset、Prefab、最新ログを確認する。HTTPタイムアウトだけで同じ生成を再送しない。
- Inspectorは共通のN式ヘッダーと日英表示を使う。参照は型を絞り、既存の手動設定を維持する。
- 作業結果をGitHubへ記録する場合は、READMEを目次として使い、ギミック・定義データ・検証状況を別ページに置く。
- カタログはIDを維持し、一覧と元定義を一緒に更新する。生成済み・割当済み・動作確認済みを区別する。
- ユーザーへの確認は進行を止める判断に限り、まとめて聞く。実行可能な作業は続ける。
